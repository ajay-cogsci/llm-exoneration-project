Area: Programming languages
Topic: static checks for small programming exercises
Question: How does variation in identifier reuse affect false warnings from syntax-pattern checks on public list-processing example programs?
Rationale: A warning rule that matches a useful surface pattern can still generate false positives when surrounding program context changes its meaning.
Contribution: Identify contexts where additional syntax information reduces false warnings and document cases where that extra complexity still misses the intended distinction.
Method: Vary identifier reuse in examples reserved by program family, define labeling rules before tuning, and have a collaborator independently recheck a subset of warning labels.

Evaluation: Report precision and recall by context with uncertainty intervals, adjudicate labeling disagreements, and evaluate on program families excluded from rule tuning.
Feasibility: Use small public inputs and university computing available through the department; schedule a pilot, comparisons and a written report within six months.
Limitations: Manual labels and template overlap can distort apparent gains; publish the labeling rules and repeat analysis after excluding near-duplicate program families.
